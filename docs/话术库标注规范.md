# 诈骗话术库标注规范（v0.1）

> 配套管线：`scripts/scam_corpus/build_corpus.py`；语料：`data/scam_corpus/corpus_v0.1.jsonl`。
> 本规范是万级话术库（极致化计划书 §三）的唯一标注依据，抽检与仲裁均以此为准。

## 一、三轴标签体系

### 轴 1：诈骗类型 `category`（8 类，单选）

| 键 | 定义 | 典型风险要素 |
|---|---|---|
| `impersonate_family` | 冒充子女/亲友，出车祸、被扣、急事借钱 | 转账、保密、时间压力 |
| `impersonate_authority` | 冒充公检法/政府机关，涉嫌犯罪配合清查 | 权威恐吓、安全账户、转账、阻止报警 |
| `fake_investment` | 虚假投资理财，内部名额高息保本 | 转账、时间压力 |
| `refund_cs` | 冒充客服，快递丢失理赔/会员扣费退款 | 验证码、屏幕共享、账户信息 |
| `lottery_prize` | 中奖/积分兑换，先交税费保证金 | 转账、时间压力 |
| `online_loan` | 网络贷款，刷流水/解冻费/保证金 | 转账、账户信息 |
| `elder_healthcare` | 养老保健品/免费体检/专家义诊 | 转账、保密（防子女阻拦） |
| `romance_pig` | 情感杀猪盘，网恋对象引导投资/借款 | 转账、保密 |

边界仲裁：同时像两类时，以「最终要钱的手法」归类（如冒充子女但最后引导投资 → `fake_investment`）。

### 轴 2：话术阶段 `stage`（4 段，单选）

| 键 | 定义 | 判别要点 |
|---|---|---|
| `opening` | 寒暄建立身份 | 无实质诉求，只解决"我是谁" |
| `buildup` | 铺垫事由 | 给出事件/理由，尚不要求行动 |
| `pressure` | 制造紧迫/恐吓 | 出现时间限制、后果威胁、情绪施压 |
| `ask` | 索要钱财/凭证 | 出现明确动作指令（转账/念验证码/点链接/人脸） |

一条话术只属于一个阶段（构建管线按阶段分格生成，天然单标签）。
v0.2 规划：多轮对话样本以 `turns[]` 数组承载，每轮独立标 stage。

### 轴 3：风险要素 `risk_elements`（10 项，多选）

`money_transfer` 转账汇款 · `account_info` 卡号密码 · `verify_code` 验证码 ·
`screen_share` 屏幕共享 · `face_auth` 人脸识别诱导 · `secrecy` 保密要求 ·
`time_pressure` 时间压力 · `authority_threat` 权威恐吓 · `safe_account` 安全账户 · `no_police` 阻止报警

判定标准：**文本中必须有显式依据**（关键词命中或语义等价表述）。类型默认要素
（`CATEGORY_RISK_MAP`）只作兜底，人工复核时可删减无依据项。

## 二、记录格式（jsonl 一行一条）

```json
{"id": "SC-000123", "category": "impersonate_authority", "stage": "ask",
 "risk_elements": ["authority_threat", "safe_account", "money_transfer"],
 "label": "scam", "text": "……", "dialect_style": "mandarin-老年男声",
 "source": "cloud:deepseek-chat", "seed_skeleton": "……",
 "self_check_risk": 0.87, "created": "2026-09-03",
 "review": {"sampled": true, "verdict": "pass"}}
```

- `label`：本库全部为 `scam`；负样本（正常家人通话）另建 `benign_corpus.jsonl`，禁止混入。
- `review.verdict`：`pass` / `fix`（附修改）/ `drop`，由抽检人填写。
- `dialect_style`：仅作 TTS 阶段提示，文本本身保持普通话书面口语（方言化在语音层完成）。

## 三、质量门禁

1. **自动门禁**（管线内）：长度 10–300 字；3-gram Jaccard ≥0.55 判近重复丢弃；
   `pressure`/`ask` 阶段经通道③自检 `risk<0.5` 丢弃（`opening`/`buildup` 本就隐晦，不过滤）。
2. **人工抽检**：每轮新增样本抽 20% 进 `review_sample.csv`，抽检人逐条判 `pass/fix/drop`；
   单轮 `drop` 率 >30% 时整轮重做并调整 prompt。
3. **脱敏红线**（继承详册 §5.3）：不出现真实姓名/卡号/电话/身份证；机构名一律虚构
   （康寿堂/中安理财等）；裁判文书来源素材必须改写至不可回溯。

## 五、负样本（benign）库

配套文件：`data/scam_corpus/benign_corpus.jsonl`（管线 `scripts/scam_corpus/build_benign.py`）。

- **类别**（6 类）：`family_chat` 家庭闲聊 · `health_care` 关心健康 · `life_reminder` 生活提醒 ·
  `festival` 节日问候 · `legit_money` 正当资金往来（近边界） · `legit_service` 正当服务来电（近边界）。
- **近边界（near_boundary=true）**：与诈骗表面相似但完全正当（子女教父母转学费、银行真实通知），
  是误拦率（FAR）的主要来源，**全部强制人工抽检**；模型自检判险的近边界样本标 `必审`。
- **过滤方向相反**：正常样本自检 risk>0.5 即丢弃（近边界类除外——那正是要收集的难例）。
- 正负两库**跨库去重**：同一句子不得既在诈骗库又在负样本库。
