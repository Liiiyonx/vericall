# 本地大模型资产复用方案

盘点时间：2026-08-31。结论：**三项资产可以直接编入谛听的融合架构**，技术路线从"双通道"升级为"三通道"。

## 本地资产清单（实测确认）

| 资产 | 位置 | 状态 | 对谛听的价值 |
|---|---|---|---|
| **deepseek-r1:7b/8b**（Ollama） | `~/.ollama/models`，9.3GB，服务已在 11434 端口运行 | ✅ 随时可调 | 话术风险分析 + 红队话术生成 |
| **SenseVoiceSmall**（FunAudioLLM） | `~/.cache/huggingface` | ⚠️ 仅 5KB 元数据，本体未下完整 | 语音转写前端（需重新下载，约 900MB） |
| **YOLOv10 best.pt + ultralytics 训练管线** | `Desktop/BlindGuard_Refactored/` | ✅ 可用 | 视频换脸检测的人脸帧定位前端 |
| wav2vec2 语音情绪 / facial_emotion | HF 缓存（聆心项目用过） | ✅ 可用 | 与鉴真任务无关，**不硬凑** |
| 智谱 ZCode、CCF 论文工程 | D:/智谱、.zcode | — | 无模型权重，无可复用项 |

## 技术路线升级：双通道 → 三通道

原方案两条通道：声学伪造检测（AASIST）+ 家人声纹确认。本地资产补上第三条：

```
通话音频流（免提旁路采集）
 ├─ 通道① 声学伪造检测 ── AASIST（训练中）→ "这是不是合成语音"
 ├─ 通道② 声纹确认 ────── 家人声纹注册比对 → "这是不是本人"
 └─ 通道③ 话术语义风险 ── SenseVoice 转写 → deepseek-r1 话术分析 → "内容是不是诈骗模式"（新增）
      └─ 三路分数决策融合 → 单一风险等级 + 适老提示
```

通道③全部用本地资产，零 API 成本、数据不出户（这本身就是答辩卖点：老人语音不上云）。

### deepseek-r1 的两个用途

1. **实时话术风险分析**：SenseVoice 转写文本 → 提示词分类（转账请求/紧急恐吓/冒充身份/验证码索取四类诈骗模式 + 正常对话）。R1 是推理模型，输出带 `<think>`，解析时取 `</think>` 之后的内容即可；嫌慢可换 `qwen2.5:7b-instruct`（注意 family 是 qwen2，同源生态）。
2. **红队数据集生成**：批量生成诈骗话术变体（每类 200 条 × 方言口语文本），配合 GPT-SoVITS 做克隆音频，喂给通道③做训练/评测。

### YOLO 的用法

视频换脸检测模块的前端：YOLOv10 检测/裁剪人脸帧 → 后端二分类器（真/伪）。BlindGuard 的 `best.pt` 是障碍物类别，不直接用；**复用的是 ultralytics 训练管线和训练经验**（数据标注→训练→导出 onnx 全流程你已跑通一遍）。

### 与 4C2026 "智能体协作"维度的呼应

通道③ 本质是一个"本地 LLM 智能体"参与决策的系统。开发过程中与 deepseek-r1 的交互记录（JSON 对话日志）直接满足 2026 版大数据赛道新增的智能体协作评分材料要求——**这部分材料是白送的**。

## 落地顺序（数据下载完之前就能做）

1. ~~SenseVoice 下载~~ → 待执行：`modelscope` 或 `hf-mirror.com/FunAudioLLM/SenseVoiceSmall`（国内镜像，约 900MB）
2. 写通道③原型脚本：`src/fusion/semantic_channel.py`（Ollama HTTP API 调用，参考 `http://localhost:11434/api/generate`）
3. 红队话术生成脚本：`scripts/generate_scam_scripts.py`（四类诈骗 × 话术模板 → r1 扩写变体）

## 注意事项

- R1-7B 在 RTX 5060 8GB 上 Q4 量化可全量进显存，但 R1 会先思考再回答，单次响应 10–30 秒——**实时通道用它偏慢**，正式系统里话术分类建议换小指令模型或规则+LLM 混合；红队数据生成不在乎延迟，用 R1 没问题。
- Ollama 的 7b 和 8b 是两个重复模型（7b 是蒸馏早期版），后续可 `ollama rm deepseek-r1:7b` 释放 4.7GB 磁盘。
