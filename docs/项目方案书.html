政策与官方动作（立意与差异化的双重支点）

  • 《反电信网络诈骗法》（2022-12-01 施行）：把"技术反制"写入法定职责，为技术型反诈工具提供上位法依据。
  • 《人工智能生成合成内容标识办法》（多部委联合发布，2025-09-01 施行）：AI 生成内容必须标识——但标识管不住"点对点通话里的实时拟声"，这就是我们的阵地。
  • 国家反诈中心 App 已上线 AIGC 内容鉴定功能（2026-07 公安部新闻发布会宣布，支持上传可疑视频/语音/图片一键检测）：官方做的是"事后上传检测"，本项目做"事中实时拦截"——这不是撞车，是最有力的立题佐证：公安部已经确认了这个威胁模型的严重性，而"实时 + 家庭声纹 + 适老交互"是官方功能没有覆盖的空白。

二、项目定位

一句话：当诈骗分子用 AI 伪造子女声音/面容打来电话时，在通话进行中实时给出风险判定，用"家人声纹 + 伪造检测 + 话术风险"三重证据劝阻老年人转账。

与现有方案的三点差异

  • 实时 vs 事后：反诈中心 App 需要用户主动上传可疑文件——被骗的老人不会觉得可疑。本项目在通话中被动监测，无需用户判断力。
  • 家庭声纹 vs 通用检测：预先注册家人声纹库，来电自称"儿子"但声纹不匹配 = 独立于伪造检测的第二重证据，也是消费级产品里没人做透的点。
  • 适老交互 vs 工具向：大字弹窗、温和话术（"这个声音有点不对，建议挂断后回拨试试"）、同步推送子女端——技术判定最终要转成老人愿意听的劝阻语言。

三、系统架构

① 采集层（终端旁路）手机 App 麦克风流（免提通话场景）／通话录音文件检测。诚实定位：微信/系统通话无法直接截获音频流，采用"免提外放 + 麦克风旁路采集"的现实路径，延迟预算 ≤ 2 秒。
↓
② 检测引擎（双模态并行）音频线：VAD 分段（3–4s 滑窗）→ 深度伪造检测（AASIST/SSL 前端，ONNX 端侧推理）＋ 声纹确认（ECAPA-TDNN vs 家庭声纹库余弦相似度）。视频线（二期）：帧级人脸篡改检测 + 时序聚合。
↓
③ 决策融合层三级置信度输出（绿/黄/红）：伪造置信度 × 声纹匹配度 × 话术风险关键词（"转账""安全账户""别告诉家人"等规则库 + LLM 判读）。融合规则可解释，评审可追问。
↓
④ 提醒与联动层老人端：大字弹窗 + 语音播报温和提示。子女端：微信服务号/小程序实时推送（来电号码、判定证据、建议话术——LLM 生成）。事件沉淀为家庭反诈台账。
↓
⑤ 数据闭环层（大数据作品的关键）误报/漏报反馈 → 红队评测集迭代；方言语音 + 家人声纹持续沉淀为自有一手数据集。

数据壁垒：红队方言评测集（自有一手数据，冲一等奖的硬通货）

  • 用开源 TTS/VC（GPT-SoVITS、CosyVoice、Seed-VC 等）对自愿者及其家人的真实声纹做克隆合成，构建"中文 + 方言 + 真实信道（电话 8kHz、免提噪声）"的攻击样本——现有公开数据集几乎全是英文/干净信道，这是公开评测分数与真实场景之间的鸿沟，也是我们独占的数据资产。
  • 伦理合规：全部采集签署知情同意书（模板随工程提供），仅用于研究与评测，不外传。

五、技术路线（四阶段）

阶段一 · 基线复现与评测管线

2026.09 – 2026.10
  • 申请并下载 ASVspoof 系列 + WaveFake + FMFCC-A/CFAD；统一 16kHz/8kHz 双信道预处理管线。
  • 复现 AASIST（ASVspoof2019 LA 已知攻击 EER<1%），跑通训练-评测闭环；同时跑 RawNet2 与 WavLM/wav2vec2 SSL 前端微调三条基线。
  • 建立跨域评测协议：英文训练 → In-the-Wild / 中文评测（预期 EER 大幅劣化，把"劣化"本身变成研究点）。

阶段二 · 泛化性攻关（学术纵深）

2026.11 – 2026.12
  • 跨语言泛化：英文+中文混训、SSL 前端对比、数据增强（电话信道仿真：编解码/丢包/免提混响）。
  • 部分伪造检测（PartialSpoof 思路）：诈骗往往只替换关键语句，全段分类器会漏检。
  • 声纹线：ECAPA-TDNN（SpeechBrain）建家庭声纹库，输出独立的第二证据流。
  • 产出副产品：一篇可投的小论文（深度伪造语音跨语言/跨信道泛化），反哺 CCF 投稿线。

阶段三 · 系统工程与产品化

2027.01 – 2027.03
  • 流式推理服务：VAD 滑窗 + 增量决策融合，端侧 ONNX 量化（延迟 ≤2s 目标）。
  • App/小程序双端：老人端大字 UI + 子女端推送；LLM 生成劝阻话术（用扣子/豆包编排，对齐 4C2026 起的"智能体协作"评分维度）。
  • 红队评测集 v1.0 完成（≥50 名自愿者、含福州话等方言），跑全链路端到端指标。

七、风险与对策

  • 通话音频流无法直接截获（最大工程风险）：微信/系统通话不开放音频接口。对策：MVP 采用"免提外放 + 麦克风旁路采集"，并在方案里诚实声明信道假设；进阶路径探索与老人机/固话厂商合作。答辩时这是"工程约束下的现实选择"，不是缺陷掩盖。
  • 跨语言/跨信道泛化差：模型在英文干净数据上 99%，到中文电话信道可能掉到 70%。对策：这本身就是阶段二的研究命题，做消融实验把劣化规律讲清楚，比假装没有强。
  • 误报伤害家人信任：误把真儿子判为假货比漏报更伤产品。对策：三级置信度 + "建议回拨确认"等非指控式话术 + 声纹证据独立呈现。
  • 与官方/大厂功能重叠：对策见定位节——实时、家庭声纹、适老交互三点差异化，并引用官方动作作佐证。
  • 与其他学生队伍撞车：方向热但方言红队数据集、适老交互设计、家庭声纹三样都做的人极少；先发跑通评测管线即领先。
