## §0 三句话结论

1. **2026 下半年不是参赛期，是改造期。** 盘点下来，2026 年所有含"智能体"命题的赛事报名窗口（数字中国 3/31、C4-AIGC 5/11、中国软件杯 7/20、教育信息技术应用创新大赛 7/20、琶洲 8/31）**到今天已全部关闭**。唯一还能做的即时动作是 2027 大创立项申报（窗口正在开放）。

2. **不需要从零做新项目。** 聆心在技术上已经是 LangGraph 多智能体系统（对话陪伴智能体 + 风险决策智能体 + RAG + 数字人智能体 + 感知-决策-工具-记忆闭环），缺的是**叙事改切**和**5 项 Agent 通用能力补强**，成本约 3–4 周；重做一个新项目的 80% 工程量会与现有资产重复，且大创**每人每批次限 1 项**、指导老师时间也只够一个。

3. **唯一的"新做"例外是信创移植分支。** 教育信息技术应用创新大赛·智能体应用应用开发实践赛要求基于**统信 UOS V25 + 国产 GPU + UOS AI 平台**开发，这是真实移植成本（4–6 周），但该赛事**国赛每校最多 2 队**、校内竞争小，是目前 Agent 赛道里确定性最高的机会。建议为它 fork 一支"聆心-信创分支"，而不是新立项。

## §2 智能体（Agent）赛道专章

### 2.1 你手上**已经是** Agent 项目 —— 不必从零重做

聆心的现有架构按主流定义就是一个多智能体系统：

| Agent 要素 | 聆心现状 | 是否达标 |
|---|---|---|
| 编排框架 | **LangGraph** 状态图，对话陪伴智能体 + 风险决策智能体 | ✅ |
| 工具调用 | WebRTC / Socket.IO / SQLite / RAG 检索 | ✅ |
| 记忆 | 会话记忆 + 风险状态机（"取最高不降级"单调状态机） | ✅ |
| 多模态感知 | emotion2vec（语音）+ FER（表情）+ pose（姿态） | ✅ |
| RAG 知识库 | 心理知识库 | ✅ |
| 数字人智能体 | 已实现 | ✅ |
| **自主规划（Planner）** | ❌ 当前是**写死的固定图**，非动态任务拆解 | ❌ **需补** |
| **工具自省 / 失败重试** | ❌ | ❌ **需补** |
| **长期记忆与个性化** | ⚠️ 有会话记忆，缺跨会话用户画像 | ⚠️ **需补** |
| **标准化接口（MCP / Function Calling）** | ❌ | ❌ **需补** |
| **可观测性（trace / 评测）** | ⚠️ 有 70 测试，缺 Agent 行为 trace | ⚠️ **需补** |
| **Agent 能力评测集** | ✅ 已有 CampusEval 702 条 + McNemar 48:0 / p=7.1e-15 | ✅✅ **这是稀缺优势** |

**关键判断**：缺的 5 项（Planner / 自省重试 / 长期记忆 / MCP / 可观测性）**都是"壳层"改造**，不动核心模型，成本约 **3–4 周**。而重做一个新项目的 80% 工程量（ASR、情感识别、RAG、部署、评测）会与现有资产完全重复。

### 2.2 决定性差异化：把 CampusEval 改名为 `LingXinAgent-Bench`

当前 Agent 赛道的普遍痛点是：**所有人都在交 demo，几乎没人交评测**。你手上已经有：

- CampusEval 702 条（146 手工 + 556 模板；测试集 631 条，crisis 8.4% / 53 条）
- B1 关键词规则对照：34.9% acc，**crisis recall 仅 9.4%（漏 48/53）**
- B2 零样本 LLM：turbo 78.9 / plus 85.3（重复 84.9±0.8）/ max 82.6，**crisis recall ≈100%**
- **McNemar 48:0，p = 7.1e-15**；Clopper-Pearson 95% CI [93.3, 100]
- 语音探针结论：韵律承载唤醒度（arousal），不承载细粒度负性类别

这套东西以"**Agent 能力评测基准 + 风险感知融合**"的名义提交，是 Agent 赛道里**极少见的硬证据**。它能一次性解决三个评审质疑：① 你怎么证明 Agent 有效？② 你怎么避免 Agent 误判高危？③ 你怎么保证可复现？

**壳一：`灵析 LingXi-Agent`（叙事壳，零新增工程量）**

### 3.5 🔴 一稿多投红线（"投多个有影响吗"）—— 分两种，性质完全相反

#### 性质对照表

| 做法 | 定义 | 性质 |
|---|---|---|
| **一稿多投 / 并行投稿** | 同一篇稿**同时**投 ≥2 个 venue，或在 A 评审期间投 B | ❌ **学术不端**，IEEE/ACM/CCF 明令禁止 |
| **串行投稿** | A 拒稿后，改投 B | ✅ 完全合规，学界常规 |
| **一稿多发 / 重复发表** | 同一内容在 ≥2 个 venue 正式发表 | ❌ 比一稿多投**更严重** |
| **扩展版再投** | 会议论文扩展 ≥30% 新内容后投期刊 | ✅ 合规，须引用原论文并明示增量 |
| **一工作多文** | 同项目不同贡献点写成多篇互引论文 | ✅ 合规，**这才是"多投"的正解** |

#### IEEE 的规定与后果

ICASSP 与 IJCNN **同为 IEEE 主办**。投稿系统有原创性勾选框，要求作者确认稿件"**当前未在其他地方审稿中**"，勾选即构成承诺。

后果（IEEE PSPB Operations Manual，实际执行、非纸面条款）：
- 一经发现 → **立即撤稿**（Xplore 上标注撤稿原因，永久留痕）
- **禁止向该 IEEE 会议/期刊投稿若干年**（常见 1–5 年）
- 通报作者所在机构

**暴露方式不是抽查，是撞审稿人**：ICASSP（Speech & Language Processing / Multimedia SP）与 IJCNN 的 reviewer pool **高度重叠**——情感计算/多模态这个圈子不大，同一篇稿子被同一位审稿人收到两次是真实会发生的事。你的题目指向性又特别强（"LLM-Augmented Multimodal Emotion Recognition … Campus Psychological Early Warning"），风险高于平均。

```
2026-09-17  投 ICASSP 2027（CCF-B）  接收率 ~40%
     │
2027-01-13  出结果
     ├── 中（40%）→ CCF-B 到手，状态升为「已录用」
     │
     └── 拒（60%）→ 吸收审稿意见，01-31 投 IJCNN 2027（CCF-C）  ~50%
                        │
                  2027-03-15 出结果
                        ├── 中 → CCF-C 到手
                        └── 拒 → 兜底投 NLPCC 2027（CCF-C，大中华区，¥0.6–0.9 万）
```

**累积成功率 ≈ 1 − 0.60 × 0.50 ≈ 70%**（且被 ICASSP 拒后经修改重投，IJCNN 命中率通常高于 50%，实际更高）。

> 对比：违规并行投两个会，最好的结果是中一个（概率同样约 70%），但要赌上**两个会同时拉黑 + 撤稿留痕 + 通报学校**。收益相同、风险天壤之别。

前两站最有价值，NLPCC 是兜底。

#### ✅ 真正该做的"多投"：把一份工作拆成多篇（一工作多文）

不是 1 篇投 4 个会，而是 4 个贡献点各写 1 篇，互相引用，全部合规：

| 论文 | 贡献点 | 建议 venue |
|---|---|---|
| **A（已完稿）** | risk-aware fusion + LLM 增强情绪识别 | ICASSP → IJCNN 串行 |
| **B（新写）** | **CampusEval 702 条**数据集与危机召回评测基准（McNemar 48:0, p=7.1e-15） | LREC 2028 / ACL Workshop / 中文核心 |
| **C（新写）** | 语音探针负面发现：**韵律只承载唤醒度，不承载细粒度负性类别** | Short paper / Workshop |
| **D（新写·谛听）** | 红队方言鲁棒性评测（粤闽 100% 漏拦、space 对抗逃避 100%） | 安全 / NLP 相关 venue |

A 用 B 做评测、B 独立描述数据集构建与统计，两篇互引即可，**不构成重复发表**。这样既能"多投"，又能同时喂饱大创结题、挑战杯大挑支撑材料（明列接受已发表/录用论文）、4C 作品书创新性章节，以及保研/评奖的论文计数。

#### ⚠️ 竞赛层面的"多投"是另一套规则

跨赛事投同一作品（如谛听同投 4C + 信安 + 软件杯 + 大挑 + 互联网+）**合规且被鼓励**，但有以下限制：

- **中国软件杯**：明列"决赛完成前在其他比赛展出、**获奖**的作品或雷同作品不得参赛" → 需书面确认（见 §4.1）
- **挑战杯大挑**：同一作品同届只能报一个类别
- **4C**：同一作品不能同时报两个类别
- **C4-AIGC**：每人限一条赛道、一支队伍、一份作品
- **大创**：每生每批次限 1 项

另需提前问院教务：部分学校**同一作品重复获奖只计一次竞赛分**，或校内对"一作多投"有额外限制。

## §4 冲突与取舍（必须提前决策的 5 件事）

### 4.1 一稿多投红线 ⚠️
> **中国软件杯官方原文**："所有参赛作品，必须是参赛团队在本届大赛期间完成的原创作品；**在本届大赛决赛完成之前在其他比赛或者平台展出、获奖的作品或雷同作品，不得参赛**。"

- 谛听若 2027-07 先拿 4C 国奖，8 月再投中国软件杯有风险。
- **对策**：软件杯作品提交（6–7 月）早于 4C 决赛（7–8 月），但"展出/获奖"判定以决赛完成为准。**报名前发邮件向组委会书面确认**，留存回复。

### 4.2 大创限项
每生每批次**只能参与 1 项** → 聆心。谛听不报。

### 4.3 C4-AIGC 限项
每人只能报**一条赛道**、加入**一支队伍**、提交**一份作品** → 聆心 Agent 版只投应用赛道（不投创作赛道）。

### 4.4 2027 年 7–8 月 = 地狱月份 ⚠️
同期撞车：4C 国赛决赛 + 中国软件杯全国总决赛 + C4-AIGC 决赛 + 信安作品赛决赛 + 大挑省赛收尾。

**建议主动取舍**：
- ✅ **必保**：4C 国赛（两件都在此）、大挑省赛
- 🟡 **二选一**：中国软件杯 vs C4-AIGC —— **选软件杯**（工信部主办，层级更稳，奖金与认可度都高于 AIGC）
- 🔵 **可弃**：琶洲（若未进复赛自然淘汰，无需取舍）

### 4.5 2027-06-14~18 IJCNN 开普敦
- 与 4C 校赛/省赛末段（3–6 月）**可能撞车** → 提前和队友分工，答辩可由队友承担。
- 需要 ¥1.5–2.7 万 → 从大创经费出（见 §3.3）。若立项失败，走"学校资助 > 导师课题 > 自费"。
- ⚠️ IEEE 要求**至少一作者全注册 + 现场参会**，否则论文可能不入 IEEE Xplore → **这不是可选项**。

## §6 数据口径与不确定性说明

1. **所有概率均为估计区间**，依据：① 各赛事官方公布的参赛/获奖数量比（如 4C 2026：4231 件 / 国一 200 → 4.73%）；② 信安作品赛 2026：1566 队 / 457 进决赛 = 29.2%；③ 福州理工学院作为应用型本科，在**省赛以上的评审中存在院校层次折价**，故本文对国赛概率一律取保守值。
2. **2027 年赛事时间为"预计"**，依据 2026 届（或最近一届）同期日程外推，须以官方通知为准。已确证的硬日期：IJCNN 摘要 2027-01-31 23:59 AoE / 通知 2027-03-15 / camera-ready 2027-04-12 / 会议 2027-06-14~18；第二十届大挑 2027 年由华东师范大学承办。
3. **确定性排序**：已确证 > 单来源 > 外推 > 估计。本文 §1 中标注"预计"的日期均为外推值。
4. **竞品密度数据**（谛听方向 20 件 / 聆心方向 91 件）来自 2026 年 4C 国赛获奖名单 PDF（145 页）程序化解析，见 `docs/国奖竞争力对比分析_聆心vs谛听.md`。
5. 本文未计入：数学建模、ACM/CCPC、电子设计、机械创新等**与两件作品无关的赛事**；亦未计入纯 CTF 类（信安实践能力赛）赛事。
